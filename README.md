# Vellar

Текстовая многопользовательская RPG для Telegram, развиваемая в постоянную
MMORPG. Управление рассчитано на чтение экранным диктором: Reply Keyboard,
текстовые команды, самостоятельные сообщения и пошаговые решения без требования
быстрой реакции. Правила интерфейса — в [доступности](docs/accessibility.md).

В игре уже реализованы путешествия, общий бой, группы, гильдии, торговля,
ремесло и развитие персонажа. Готовность к устойчивому открытому выпуску ещё
не подтверждена: [аудит от 08.10.2026](docs/project-audit-2026-10-08.md)
выявил ошибки роспуска гильдии, повторного вклада, цены старой карточки,
переноса износа и зачёта заданий. Сохранение общего боя ещё зависит от кэша.

## Текущая игра

| Область | Что есть в коде |
| --- | --- |
| Мир | 15 городов, 75 локаций, 75 городских подземелий, общие волны и поколения округи |
| Герой | Уровни 1–150; 16 рас, 8 классов, 64 обычные черты и 40 черт-вех |
| Развитие | 480 записей умений, 1280 вариантов выучки, 112 веток специализации на уровнях 30, 75 и 150 |
| Бой | Один пошаговый движок для PvE/PvP, отрядов и вмешательства; состояния и повадки противников |
| Сюжет | 56 обычных заданий, пять актов, обучение и 336 испытаний специализации, созданных из данных |
| Ремесло | 11 ремёсел, сбор инструментами, качество, износ, ремонт, разбор и перековка |
| Люди | Отряды до 5, гильдии от 12 до 30 мест, казна, склад, подряды, войны, адресные сделки |
| Обслуживание | Панель смотрителя, блокировки, журнал, правки содержимого, копии и наблюдение за процессом |

Срез проверен по файлам 08.10.2026. Подробности и границы доказательств — в
[текущем состоянии](docs/current-state.md). Количество записей не является
оценкой качества контента или длительности прохождения. Общесерверный сюжетный
выбор, публичный рынок и развитая игра на максимальном уровне остаются в плане.

## Запуск

Требуются Python 3.14 и uv. Токен хранится только в локальной `.env`;
образец — `.env.example`, токен выдаёт [BotFather](https://t.me/BotFather).
Существующую `.env` не перезаписывать. Неисправное окружение, обнаруженное при
аудите 25.09.2026, восстановлено 26.09.2026 на Python 3.14.6.

| Команда Windows | Назначение |
| --- | --- |
| `Start.bat setup-db` | Первичная настройка роли и базы локального PostgreSQL |
| `Start.bat` или `Start.bat solo` | PostgreSQL этой машины; экран и бой в памяти процесса |
| `Start.bat local` | Всё в памяти; после выхода прогресс пропадает, только для разработки |
| `Start.bat docker` | PostgreSQL, Redis и бот в контейнерах |
| `stop.bat` | Создать дамп; остановить поднятый стек с сохранением данных |

Локальный PostgreSQL устанавливается отдельно. В `solo` персонажи и вещи
сохраняются, но незавершённая сессия обрывается при перезапуске. В режиме с
Redis бой тоже имеет срок хранения; сейчас нельзя обещать неограниченную паузу.
Запуск и обновление — в [развёртывании](docs/deployment.md). Скрипт Start.bat
также устанавливает Git-хук и штампует версию; не запускать его ради чтения документов.

Ручная установка зависимостей:

```powershell
uv sync --frozen
```

Применять `uv run alembic upgrade head` только после проверки адреса базы и
наличия пригодной резервной копии; затем запускать `uv run python -m mmorpg.main`
с выбранным `APP_ENV`. Для `local` внешняя база и миграции не нужны.
Режимы приложения: `local` — память, `solo` — PostgreSQL и память сессии,
`dev` — PostgreSQL и Redis с опросом Telegram, `prod` — те же службы с вебхуком.

## Проверки

Начать с [порядка проверок](docs/verification.md): интеграционные тесты требуют
отдельные адреса служб. Полный запуск использует `docker-compose.test.yml` и
`scripts/m00-verify.ps1`; отсутствие служб считается ошибкой. Результаты
последнего прогона — в [порядке проверок](docs/verification.md).

```powershell
uv run ruff check .
uv run ruff format --check .
uv run mypy
uv run pytest -m "not integration" --ignore=tests/content/test_changelog.py
```

Полная проверка на отдельном стенде: `pwsh -File scripts/ci.ps1`
(на Linux/macOS — `./scripts/ci.sh`). Порог покрытия домена — 90 процентов.
На 08.10.2026 проверки M01.1–M01.4 и всего M02 на отдельном стенде прошли;
тесты истории изменений, запускающие Git, выполнены по явному поручению выпуска.
Живая игра в Telegram
и доступность с NVDA/JAWS проверяются отдельно.

## Устройство

`src/mmorpg/domain/` — чистые правила; `application/` — сервисы;
`infrastructure/` — PostgreSQL, Redis и загрузка TOML;
`presentation/telegram/` — обработка действий и экраны.
Постоянное содержимое разделено между 15 файлами `content/`.
Последняя миграция в файлах — `0034`; установленная версия рабочей базы этим
не подтверждается. В Compose используется PostgreSQL 17 и Redis 7.

Полный [указатель документации](docs/index.md) включает технические справочники,
правила мира, игровые системы, историю решений и требования к выпуску.
