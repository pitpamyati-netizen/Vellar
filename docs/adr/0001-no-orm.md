# ADR 0001 — Без ORM: asyncpg и явный SQL

Статус: принято (2026-08-12)

## Обстоятельства

У бота бюджет задержки p95 — 100 мс на обновление. Обычное обновление трогает одну-две
строки по первичному ключу. ORM добавляют накладные расходы на каждый запрос (карта
тождеств, единица работы, ленивая загрузка), и они невидимы до той минуты, когда
выстреливают неожиданным лишним походом в базу; к тому же ORM подталкивают к графам
сущностей, через которые заботы хранения протекают в домен.

## Решение

Никакого ORM. Хранилища в `mmorpg/infrastructure/persistence/` пользуются `asyncpg` с
явным SQL и подготовленными запросами и возвращают сущности домена, собранные руками.
Изменения схемы версионируются Alembic, а его миграции несут сырой SQL, а не
автоматически выведенную разницу моделей.

## Последствия

- Каждый запрос виден и его можно прочитать глазами; случайного N+1 не бывает.
- Сущности домена — обычные замороженные dataclass без базового класса хранения.
- Разбор строки в сущность пишется руками один раз на хранилище.
- Alembic берётся чисто как исполнитель миграций: метаданных моделей, из которых можно
  было бы вывести миграцию, нет, поэтому миграции пишут руками.
