# ADR 0001 - No ORM, asyncpg with explicit SQL

Status: accepted (2026-08-12)

## Context

The bot has a p95 latency budget of 100 ms per update. A typical update touches one
or two rows by primary key. ORMs add per-query overhead (identity map, unit of work,
lazy loading) that is invisible until it fires an unexpected extra round trip, and
they encourage entity graphs that leak persistence concerns into the domain.

## Decision

No ORM. Repositories in `mmorpg/infrastructure/persistence/` use `asyncpg` with
explicit SQL and prepared statements, and return domain entities built by hand.
Schema changes are versioned with Alembic, whose migrations contain raw SQL rather
than autogenerated model diffs.

## Consequences

- Every query is visible and reviewable; no accidental N+1.
- Domain entities are plain frozen dataclasses with no persistence base class.
- Mapping rows to entities is written by hand once per repository.
- Alembic is used purely as a migration runner; there is no model metadata to
  autogenerate from, so migrations are authored manually.
