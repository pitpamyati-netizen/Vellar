# ADR 0108: закреплённая карта локации

Дата: 16 октября 2026 года. Статус: принято по прямому поручению пользователя.
Заменяет автоматическую перестройку из [ADR 0035](0035-a-location-relays-its-whole-layout.md)
и уточняет поколение из [ADR 0090](0090-durable-battles-and-sessions.md)
и [ADR 0107](0107-free-ranks-and-scoped-location-actions.md).

## Причина

Проверка кнопок не устраняла смену карты. Старое правило вычисляло поколение
по сумме волн всех узлов. Как только сумма пересекала очередные двенадцать
волн, менялись имена и виды узлов, связи и боевой состав всей локации.
Остатки хранились под прежними номерами узлов и попадали уже в другие места.
Выработка другими игроками могла вызвать это прямо во время вылазки.

## Решение

1. `location_epoch` возвращает закреплённый номер карты из `epoch_offset`.
   Поле сохраняет прежнее имя для совместимости. Пополнение меняет только
   волну опустевшего узла; личность остальных узлов и стай остаётся прежней.
2. При первом чтении хранилище сохраняет прежний действительный номер,
   включая старое смещение и сумму уже обновлённых волн, в
   `loc:<город>:<место>:layout-generation`. Последующие чтения не пересчитывают
   его. Новая локация получает нулевой номер. Прежние карты сохраняются.
3. PostgreSQL закрепляет карту под общей операцией команды: сбой отменяет
   запись, одновременные первые чтения согласованы. Redis использует
   однократную установку с проверкой существующего значения. Постоянные
   игровые режимы хранят номер в PostgreSQL; срок кэша на него не влияет.
4. `build_location` без явного номера использует номер сессии. Это исключает
   случайный показ нулевой карты вместо сохранённой ненулевой.
5. Состояние «выработана» определяется числом волн, отдельно от номера карты.
   Выработка продолжает влиять на прежние правила экономики и состояния
   округи. Экран больше не обещает перестановку троп.
6. Явный сброс смотрителем в PostgreSQL сохраняет прежний смысл: следующий
   номер карты, пустые узлы, защита старых сессий и владения встречами.
   Обычное действие игрока новую карту не создаёт.

## Сохранность и проверка

Схема SQL не меняется: новый ключ использует `gameplay_state`. Персонажи,
добыча, потраченные места волн и снимки начатых боёв не заменяются.
Копия PostgreSQL содержит закреплённую карту вместе с остальным миром.

Проверяются прежний ненулевой номер, повторные пополнения, первое действие
без предварительного чтения, одновременные первые чтения, откат при сбое,
новый экземпляр хранилища, потеря Redis и восстановление резервной копии.
Все локации каталога проверяются с четырьмя номерами карт.
Подробные результаты и границы — [протокол](../stable-nodes-2026-10-16.md).
