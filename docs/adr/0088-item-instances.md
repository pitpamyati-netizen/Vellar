# ADR 0088 — Износ остаётся с конкретной вещью

Статус: принято, реализовано 08.10.2026 (M01.5).

Уточняет [0056](0056-gathering-happens-at-the-vein-and-needs-a-tool.md),
[0057](0057-gear-wears-out-and-the-forge-mends-it.md),
[0059](0059-gear-carries-affixes-and-a-stamp.md) и
[0084](0084-economic-operation.md). Правила работы инструмента и цены ремонта
сохранены; прежнее объединение одинакового снаряжения заменено экземплярами.

## Причина

Общий счётчик по виду вещи чинил её при передаче другому герою и делал новую
покупку изношенной. Резерв продажи и склад сохраняли только вид и количество.

## Решение

Каждое снаряжение и каждый инструмент получают постоянный номер в
`item_instances`. Ссылка имеет вид `шаблон!номер`; материалы сохраняют прежний
общий остаток. Номер выдаёт хранилище, чистые правила его лишь передают.
Числа и аффиксы считаются из шаблона, а износ хранится по номеру. Отдельный
экземпляр имеет количество один. Номер явно различает подписи кнопок и текстовые
команды; устаревшая подпись не выбирает другую одинаковую вещь.

Инвентарь, надетые вещи, склад и резерв продажи передают одну и ту же ссылку.
SQL проверяет единственное место экземпляра в конце общей транзакции, позволяя
промежуточное перемещение между её записями. Ремонт изменяет только выбранный
экземпляр. Перековка меняет шаблон и сохраняет номер с износом; реликтовая сборка
по уровню сохраняет ссылку. Повтор команды остаётся под защитой M01–M02.
При чтении героя хранилище подставляет нынешний износ его собственных вещей;
старое сохранение прежнего владельца не записывает износ чужого экземпляра.
Неизменённое поле износа не перезаписывает нынешнее состояние вещи: после
возвращения старое сохранение владельца также не чинит её.

## Перенос прежних данных

Миграция `0035` разделяет каждое прежнее количество снаряжения и инструмента.
Все одинаковые копии героя получают прежний общий износ: прежняя модель не
позволяет доказать, какая из них работала. Количество, золото и материалы
сохраняются. Надетые вещи получают отдельные номера, поскольку прежде они уже
были вынуты из сумки. Резерв старой продажи нескольких вещей хранит список
номеров; возврат, принятие и административный откат перемещают каждый из них.
Старая покупка связывается с наличными экземплярами указанного владельца;
если их уже недостаточно, исполнение отказывается, а резерв золота возвращается
прежним путём отмены/истечения.

В старом складе износ отсутствовал. Для его вещей берётся максимальный
известный прежний износ того же вида среди героев: это консервативная политика,
которая сохраняет имущество и не обещает восстановить неизвестное состояние.
Исторические уже завершённые сделки не получают выдуманных номеров;
административный возврат не забирает вместо них чужой новый экземпляр.
Обратное объединение экземпляров запрещено; возврат версии требует
проверенной резервной копии. Старые кнопки с видом без номера требуют нового
выбора из сумки. Восстановление старого состояния общего боя остаётся M03.

## Проверка

Проверки охватывают разные износы одинаковых вещей, покупку новой, перенос,
склад, резерв/расчёт/откат продажи, ремонт, перековку, повтор, отмену и двух
конкурирующих получателей. Схемы `0030` и `0034` перенесены с сумками,
надетыми вещами, инструментом, материалами, складом и двойным резервом.
Подробный результат — [протокол](../verification-m00-m01-2026-10-08.md).
Telegram и экранные дикторы проверяются отдельно.
