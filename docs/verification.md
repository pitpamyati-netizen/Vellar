Текущая проверка первой сессии, истории, чтения и развития —
[протокол M04 от 08.10.2026](verification-m04-2026-10-08.md).
Проверка постоянного боя, паузы, расчёта и встреч —

## Разные уровни доказательства

| Проверка | Что доказывает | Чего не доказывает |
| --- | --- | --- |
| Чтение кода и каталогов | Наличие правил, путей исполнения, структуры и рисков | Что сценарий реально прошёл |
| Ruff, mypy, тесты без служб | Стиль, типы, отдельные правила и имитации сценариев | Поведение PostgreSQL/Redis и Telegram |
| Интеграционные проверки | Запросы и операции настоящих служб на тестовом стенде | Удобство игры и доступность для человека |
| Сбой, повтор, конкуренция | Сохранность завершённых операций в испытанных сценариях | Любой мыслимый сбой или масштаб |
| Нагрузка целого пути | Задержки и ошибки при указанном составе действий | Непроверенное число пользователей или иной профиль игры |
| Ручная игра | Понятность, доступность, связь между людьми в данном сценарии | Надёжность всех операций без автоматических проверок |

## Окружение

Приложение требует Python `>=3.14,<3.15` и зависимости из `uv.lock`.
26.09.2026 Python 3.14.6 установлен через `uv python install 3.14`, а `.venv`
пересоздана через `uv venv --python 3.14 --clear .venv`. Зависимости установлены
командой `uv sync --frozen`. На иной машине нужна такая же совместимая версия;
не понижать требование Python ради запуска тестов.

Порядок после восстановления инструментов:

```powershell
uv sync --frozen
uv run python --version
uv run ruff check .
uv run ruff format --check .
uv run mypy
uv run pytest -m "not integration" --ignore=tests/content/test_changelog.py
```

Документы проверять как UTF-8: TOML, ссылки и заголовки. Это не заменяет загрузку
содержимого игрой; игровые тесты ради правки текста не добавлять.

## Интеграционные тесты: отдельный стенд обязателен

`docker-compose.test.yml` позволяет поднять отдельные PostgreSQL и Redis на портах
55432 и 56379 с собственными томами. На машине проверки Docker не было: для
прогона создан отдельный кластер PostgreSQL 17 на порту 55432 и временный Redis
8.0.5 на порту 56379. Не запускать обычный Compose игры.
На машине с Docker и клиентскими инструментами PostgreSQL выполнить:

```powershell
docker compose -f docker-compose.test.yml up -d --wait postgres redis
$env:VELLAR_TEST_POSTGRES_DSN = "postgresql://vellar_test:vellar_test@127.0.0.1:55432/vellar_test"
$env:VELLAR_TEST_REDIS_DSN = "redis://127.0.0.1:56379/0"
pwsh -File scripts/m00-verify.ps1 -PgBin "C:\Program Files\PostgreSQL\17\bin"
```

Если `psql`, `pg_dump` и `pg_restore` уже в `PATH`, `-PgBin` не нужен. В текущем
сеансе использован адрес PostgreSQL без пароля, поскольку временный отдельный
кластер допускает только локальное доверенное соединение; `.env` не менялась.
Сценарий проверяет адреса и запускает `scripts/ci.ps1`. Проверка целиком требует
живых PostgreSQL и Redis: отсутствие
адреса, службы или схемы теперь ошибка. Имя базы PostgreSQL оканчивается на
`_test`; обе службы используют другие узлы или порты, чем приложение.
Перед миграцией сценарий временно направляет `POSTGRES_DSN` в тестовую базу;
рабочий `.env` не меняется. Для проверки без служб остаётся
`uv run pytest -m "not integration" --ignore=tests/content/test_changelog.py`.
Обычный `ci.ps1` исключает `tests/content/test_changelog.py`: эти тесты сами
запускают Git. По действующему правилу проекта Git используется только по
прямой просьбе пользователя. Без такой просьбы указывать их как пропущенные;
при явном поручении запускать отдельно и записывать результат.

После основных тестов сценарий создаёт пустую базу и проводит всю цепочку
миграций до актуальной вершины (`0036`), добавляет контрольного героя с золотом и вещами, снимает копию
и восстанавливает её в другую базу, сверяя персонажа и журнал. Затем
создаёт схему `0030`, добавляет контрольного героя, копирует её,
обновляет копию до актуальной вершины и проверяет уровень, опыт, характеристику, кошелёк,
банк, снаряжение и количество в сумке. Это проверка
совместимости с созданной прежней схемой; она не заменяет отдельное испытание
реальной старой резервной копии, если такая будет предоставлена. Копия также
сверяет постоянную отметку сводки и ожидающий ответ M02. Все временные
базы находятся внутри тестового PostgreSQL.

Точки `gift.after_debit`, `offer.after_open`, `offer.after_stake` и
`settle.after_*` позволяют испытанию остановить сделку между записями или
управляемо переплести два действия. Испытания M01 проверяют откат всех частей
при этих остановках, повтор и конкуренцию на настоящем PostgreSQL.
В конце сценарий запускает
нагрузку на тестовую базу. Числа задержки и результат каждого шага записываются
в `backups/m00-*.txt`. Код нагрузки `0` — успех, `3` — превышение бюджета
задержки. Код `2` означает ошибки действий или неверные параметры, `1` —
аварийное завершение; сценарий M00 отвергает оба. Пустая нагрузка, отрицательная
или бесконечная пауза не допускаются. Числа охватывают хранилища, без Telegram.

## Проверки до расширения аудитории

- Две покупки последней вещи; два действия одного героя; вмешательство и ход
  в одном бою; торговля одновременно с наградой и банком.
- Остановка до записи, во время записи и после записи до ответа. Повтор одной
  команды после рестарта возвращает согласованный результат без второй награды.
- Потеря Redis и перезапуск solo: награда за период и предел выемки не забываются.
- Обновление версии контента во время боя; чтение сохранения прежнего выпуска;
  миграция вперёд и проверенный способ восстановления из копии.
- Нагрузка с одним и несколькими участниками, массовое событие, переполнение
  очереди Telegram и 429. Измерять обработку, ожидание отправки и полный ответ
  отдельно. Проверка хранилищ из `loadtest.py` остаётся только частью результата.
- Ручной проход создания, обучения, сумки, рынка, сбора отряда и боя с NVDA/JAWS
  и двумя настоящими аккаунтами. Автоматические проверки текста этого не доказывают.

сообщения в очередь называется сохранением для отправки. Отмена ценностей
и самой строки очереди проверена на PostgreSQL, ошибка приёмника — в памяти.

коммитом выполняет их все на том же отдельном стенде без пропусков.
