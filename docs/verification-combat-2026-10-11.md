# Исправление входа в бой от 11.10.2026

## Причина и изменение

В журнале 11.10.2026 повторялся `ValueError` из `atomic_action` при вызове
`open_fight` игровым обработчиком. Хранилище экрана `PostgresStorage` передавалось
вложенному обработчику, но отсутствовало в участниках внешней команды.
Проверка сохранности отклоняла такую команду ещё до открытия боя.

Ошибка воспроизведена через `build_application` в режиме `solo`: выбор
«Разведка» в подземелье вернул тот же текст «Что-то пошло не так, действие не
выполнено» и ту же последовательность мест ошибки, что в рабочем журнале.
До этого проверки M03 создавали готовый бой вручную и не проходили реальный
путь от игрового экрана через сборку приложения к началу боя.

`CommandMiddleware` теперь заранее получает хранилище экрана при сборке
приложения. Общий сбор участников `atomic_action` также распознаёт хранилище
в контексте экрана. Проверка чужих участников не отключена: экран, бой, герой
и ответ входят в одну прежнюю операцию. Новая миграция не требуется.
Исправление соответствует [ADR 0090](adr/0090-durable-battles-and-sessions.md).

## Проверки

`tests/integration/test_combat_entry.py` проверяет настоящее собранное
приложение в режимах `solo` и `dev`, с настоящим PostgreSQL и отдельным Redis.
Отправка Telegram заменена записывающим приёмником.

- Вход из локации и из подземелья сохраняет боевой экран и занятость героя.
- Атака и защита меняют бой; повтор того же сообщения не создаёт бой и не
  выполняет второй ход.
- Пауза и продолжение не меняют версию боя.
- Управляемый сбой после открытия отменяет бой, занятость, экран и ответ
  вместе; повтор той же команды после отмены успешно открывает бой.

Связанный набор новых проверок и `test_durable_battle_m03.py` прошёл:
24 теста. После исправления тестовых сборщиков спуска и поединка прошли
все 269 интеграционных тестов, без пропусков.

Общие результаты:

- `uv run ruff check .` и `uv run ruff format --check .` — успешно.
- `uv run mypy` — успешно, 204 файла приложения.
- `uv run pytest -m "not integration" --ignore=tests/content/test_changelog.py
  --cov=src/mmorpg/domain --cov-fail-under=90` — 2863 теста;
  покрытие игровых правил 94,29 процента.
- `uv run pytest -m integration -x -rs` — 269 тестов.
- `uv run pytest tests/content/test_changelog.py` — 20 тестов;
  Git разрешён явным поручением коммита и отправки.
- Четыре изменённых документа, 166 местных ссылок и все TOML-каталоги
  прочитаны и проверены. В истории изменений добавлена версия 1.82.

Первый общий запуск обнаружил старые тестовые сборщики без хранилища экрана
и отсутствие `pg_dump` в пути инструментов. Сборщики M03, M06 и PvP M08
обновлены; путь PostgreSQL добавлен только процессам проверки.
Отдельный прогон копий выявил разные правила сортировки исходной и
восстановленной тестовых баз. Стенд пересоздан с общей сортировкой ICU
`ru-RU`; после этого все интеграционные проверки, включая копии, прошли.

## Изоляция и ограничения

Стенд использует отдельные PostgreSQL 17 на порту 55432 и Redis 8.0.5 на
порту 56379. Рабочая `.env`, база игроков и запущенная игровая служба не
изменялись. Сетевые ошибки Telegram в журнале не являются причиной этого
отказа. Настоящая игра в Telegram и прослушивание NVDA/JAWS не выполнялись.
Исправление появится в запущенном процессе после обновления и перезапуска.
