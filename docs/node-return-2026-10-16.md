# Возврат из боя к настоящему узлу: 16 октября 2026 года

## Причина повторной ошибки

Закрепление карты из [ADR 0108](adr/0108-stable-location-layouts.md) устранило
перестройку при выработке. Однако отдельный возврат из боя не читал общее
состояние локации. Отрисовка подставляла пустое состояние с номером карты 0:
другую раскладку, все стаи живыми, без блуждающего входа и соседних боёв.
Следующее нажатие уже проверялось по действительному миру и отвергалось.

Присланный случай воспроизведён с обычным мировым сидом `vellar-prime`, Дубно,
локацией 1 и узлом 2. Карта 0 даёт «Засаду» с тропами 0, 4, 5. Сохранённая
карта 2 даёт «Стража прохода» с тропами 0, 5, 6. Эти данные полностью
совпадают с двумя раскладками в жалобе. Семь новых проверок до исправления
завершились ошибкой; это отдельная причина, не продолжение выработки карты.

## Изменение

Возврат теперь читает локацию, согласует поколение, волну и оставшиеся стаи,
сохраняет показанные свойства противников и появление подземелья. Перед
отправкой читаются соседние игроки и занятые стаи. Текущий момент передаётся
экрану, поэтому опустевший узел правильно сообщает оставшееся ожидание.
Прежнее намерение расхода из узла при возвращении не повторяется.

Обычный возврат сохраняет позицию. Явный сброс смотрителем во время боя
по-прежнему возвращает ко входу новой карты с объяснением. Городские бои
не читают несуществующую локацию. Чистая отрисовка без общего состояния
сохраняет номер карты сессии; рабочий возврат всегда читает настоящие остатки.

Начатый бой завершает расчёт по сохранённому содержимому. Возврат берёт
текущий мир, чтобы обновление каталога во время боя не создавало ещё один
неверный экран. Продолжение подземелья сохраняет прежние правила захода.

Схема SQL, карты, персонажи, награды и прогресс не сбрасываются.
Запись обновлений — 1.96. Уточняются пути показа по
[ADR 0107](adr/0107-free-ranks-and-scoped-location-actions.md) и ADR 0108.

## Проверки

Проверки без внешних служб: сохранённые карты 2 и 7; пустой и частично
вычищенный узел; вход в подземелье и возвращение из него; соседний бой;
новая волна и немедленная атака; каждая предложенная тропа; явный сброс;
городской возврат без вылазки. Девять новых сценариев прошли.

Через `build_application`, настоящие PostgreSQL/Redis и обработку сообщения
проверяются победа, возврат и следующее действие; полный и частичный расход
узла; обновление каталога во время боя; повтор возвращения без второй
награды; управляемый сбой перед завершением записи и успешный повтор.
Оба постоянных режима (`solo` и `dev`) используют свою обычную сборку.

Полный прогон завершён на Python 3.14.6, отдельном PostgreSQL 17 с ICU
`ru-RU` на порту 55432 и Redis на порту 56379. Рабочая `.env` не менялась.

```powershell
pwsh -File scripts/m00-verify.ps1 -PgBin "C:\Program Files\PostgreSQL\17\bin" -ReportPath backups/node-return-final-verification.txt
```

Один пропуск относится к прежнему сценарию блуждающего подземелья: тестовый
герой проигрывает поход, поэтому условие исчезновения входа после победы
не проверяется. Новые сценарии узлов и SQL не пропущены.
Сохранились прежние предупреждения Pydantic при записи
неизменяемых словарей; чтение, повторное сохранение и восстановление проверены.
Полный журнал и копии находятся в игнорируемом `backups/`.

Первый полный запуск хука коммита выявил неверное ожидание прежнего SQL-теста
заказа: отменная работа законно сохраняет половину сырья, а тест всегда
ожидал полный расход. В тесте явно заданы обычное и отменное качество,
проверяются точные остатки победившего мастера и второго участника.
Игровые правила ремесла не менялись. Это добавляет один вариант проверки
к 324 сценариям PostgreSQL/Redis полного прогона выше.

на GitHub сохраняют исправление в исходниках; запущенная игра получает его
после отдельного обновления службы. Объявления игрокам не отправлялись.
